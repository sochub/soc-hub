# DFIR-IRIS (dfir-iris/iris-web) community demand: feature requests, pain points, praise

Research date: 2026-10-18. All GitHub reaction/comment counts were pulled live from the GitHub REST/GraphQL API on that date (search endpoint `https://api.github.com/search/issues?q=repo:dfir-iris/iris-web+is:issue...&sort=reactions-%2B1` and `sort=comments`, plus `gh api graphql` for Discussions). Repo snapshot that day: 1,595 stars, 334 forks, 439 open issues, Discussions enabled, last push 2026-10-05 — [dfir-iris/iris-web](https://github.com/dfir-iris/iris-web). Latest stable release v2.4.29 (2026-08-10); tags `v3.0.0-beta.1`…`v3.0.0-beta.6` exist but have no GitHub Release objects (404 on `/releases/tags/v3.0.0-beta.6`) — [releases](https://github.com/dfir-iris/iris-web/releases).

Important context on how to read reaction counts: this is a low-reaction community. The single most-upvoted issue in the repo's history has 14 👍; everything else is ≤8. "Demand" below is therefore triangulated from reactions + comment counts + duplicate/recurring issues + Discussions + external write-ups, not reactions alone.

## Key Question 1: Which open GitHub issues / feature requests have the most reactions or comments? (ranked top 25)

### Takeaway
OIDC/OAuth SSO is by far the single most-demanded item (14 👍, 21 comments, open since Jan 2024, still open; a separate Discussion asks whether OIDC is "officially supported"). Behind it the demand clusters into: threat-intel integrations (OpenCTI 8 👍, MISP push), evidence chain-of-custody (5 👍), note/timeline UX quality-of-life (drag-drop images, "now" timestamp, PDF export, note locking/auto-save), per-customer/tenant permissions, scheduled/cron automation of modules, time tracking + SLA/KPIs, and an "Artifacts" staging area distinct from IOCs.

### Inferences
- The maintainers' own roadmap statement ("we have decided to pause the development of new features and focus on the core functionalities and stability… We do not provide a long-term roadmap") explains why 2022–2024 FRs with the most reactions remain open — demand accumulates rather than being served — [Source](https://docs.dfir-iris.org/latest/roadmap/).
- Many high-demand items are small UX affordances (now-button, drag-drop images, PDF export, keyboard navigation, table view for alerts) rather than big subsystems; a competitor can win on polish cheaply.
- The "Ideas" discussion "Chats in Cases interface" (2024) was evidently acted on: v3 beta ships "War Rooms: real-time chat, slash commands, per-room teams" — [Source](https://docs.dfir-iris.org/latest/).

### Gaps
- The GitHub Projects roadmap board (`github.com/orgs/dfir-iris/projects/1`) could not be read: the API requires the `read:project` token scope, which the local `gh` token lacks.
- v3.0.0-beta.x release notes could not be retrieved (no Release objects on the tags; the docs "Migrating to IRIS v3" page URL guessed returned 404). What is known of v3 comes only from the docs landing page and v3-preview labelled issues (see Q2).

## Key Question 2: Recurring pain points users report

### Takeaway
The recurring pain points, in rough order of frequency across issues/discussions/blogs: (1) data-loss and concurrency bugs in Notes; (2) Docker/upgrade/DB-migration breakage; (3) alert triage ergonomics (card-only view, no sort, timezone confusion, no SLA); (4) MISP/VirusTotal module enrichment silently not displaying; (5) permissions that stop at case-level ACLs with no customer/tenant scoping and no write-without-delete; (6) report generation fragility (DOCX template errors, markdown not rendered, sync generation); (7) API v1 inconsistencies driving a long-running API v2 rewrite; (8) container image CVE load and lack of sub-path/K8s friendliness.

### Inferences
- Notes reliability is the most damaging pain point: a 3-👍 bug where a team abandoned the in-app editor is a direct churn risk and an obvious differentiator (autosave + optimistic locking/CRDT or at minimum per-note version history).

- Permission model demand is specifically *customer/tenant-scoped roles* and *separating write from delete*, both of which map directly onto a memberships/role model.

### Gaps
- No quantitative performance complaints with numbers (event counts, latency) beyond the 2022 ">300 assets" note.

## Key Question 3: What external write-ups say IRIS does well and lacks (blogs, comparison articles, talks)

### Takeaway
External commentary is thin and mostly 2022–2023 plus a few 2024–2026 comparison pages. Consistent praise: clean/fast UI, API-first design, modules/hooks extensibility, visual timeline and asset graph, single-Postgres simplicity, LGPL licence, and being the de-facto free successor after TheHive 5 went commercial. Consistent gaps: fewer analyzers than Cortex, alert ingestion limited to API/manual, limited MITRE ATT&CK support, no official TheHive migration tool, small community (~1.5k stars), ops burden (hardening, backups, CVEs), and (historically) no case templates/Timesketch link.

### Cited Findings
- SANS ISC (Tom Webb, 2023-05-24): "This project is very active and doing a great job with adding features"; likes the assets section ("quickly seeing which systems are involved") vs creating a TheHive task per device; limitations: "no predefined ATT&CK techniques, though most items can be tagged", "Elastalert has no direct support yet", "Modules and enrichment are limited"; context: TheHive 5 "moved to a paid model and version 4 no longer receives support" — [ISC diary 29880](https://isc.sans.edu/diary/29880).
- Koen Van Impe (2022-01-05): interface "slick and well-thought-out"; "everything is available via an API"; automatic asset relation graph; missing: case templates ("no option to start a case based on a pre-defined template" — contrasted with TheHive), Timesketch link, MISP integration, prettier timeline, image export of timeline (later corrected via PR #35); "not a big fan of adding the evidences directly to DFIR-IRIS" — [vanimpe.eu](https://www.vanimpe.eu/2022/01/05/incident-response-case-management-dfir-iris-and-misp/).
- Pi Stack (2026-05-17) "Self-Hosted SOC Case Management: TheHive vs Cortex vs IRIS": IRIS "designed from the ground up for collaborative incident response", "modern" UI, single PostgreSQL vs TheHive's Cassandra+Elasticsearch; gaps: built-in IOC analysis vs Cortex "100+ analyzers", alert ingestion "Manual and API", "no official migration tool", ~1,491 stars vs ~14,500; recommends "TheHive for alert triage and IRIS for deep investigations" — [pistack](https://www.pistack.xyz/posts/2026-05-17-self-hosted-soc-case-management-thehive-cortex-iris-guide/).
- Staquest comparison (2026 page): TheHive scored 7.7 vs IRIS 7.1 (site-weighted score); IRIS "dedicated timeline view" vs TheHive "basic case notes for evidence timelines"; TheHive on Cassandra+ES vs IRIS on PostgreSQL — [staquest](https://staquest.com/compare/dfir-iris-vs-thehive).
- SOCFortress (Medium): "the modification to the license at the end of 2022 resulted in a significant reduction of the features available in the free version [of TheHive]"; calls IRIS modules "the most compelling feature of IRIS", working "much like Cortex analyzers and responders" (page returned 403 on fetch; claims via search snippets) — [socfortress.medium.com](https://socfortress.medium.com/your-open-source-incident-response-platform-e9d839f02454).
- MSSP Alert lists IRIS among "5 Open-Source Incident Response Tools for MSSPs" citing modules and API extensibility — [msspalert.com](https://www.msspalert.com/native/5-open-source-incident-response-tools-for-mssps).
- itechguides comparisons credit IRIS with "evidence hashing, chain-of-custody support, audit trails and manifest export" and flag "self-hosted deployment places infrastructure responsibility on the team" and "extending the platform may require Python module development"; scores marked largely "Not published" (low reliability) — [itechguides](https://www.itechguides.com/compare/dfir-iris-vs-cydarm/).
- FLOSSK OpenCatalog: maturity "Growing", maintenance active, main limitation "operational effort for hardening and backups" — [catalog.flossk.org](https://catalog.flossk.org/tools/dfir-iris).
- Certbar (Aryan Patel, 2024-10-11): dashboard "highly customizable"; Activities module gives an audit trail; but the article is largely speculative orientation, not an evaluation — [certbar.com](https://certbar.com/technical-blogs/navigating-dfir-iris-part-2).
- Habr (Protekt, SIEM + n8n + Cortex + MISP + IRIS series): IRIS used as the case system; alerts easy to create by passing fields via API; case templates give consistent structure; friction: template ID required for API case creation, assets must be added after creation with per-type calls, admin password handling via `IRIS_ADM_PASSWORD` — [habr.com/ru/articles/992838](https://habr.com/ru/articles/992838).
- CERT.PT/IPB talk (2025-05-06): describes IRIS as "open-source, similar to TheHive, flexible and with an active community"; modules used: MISP, IntelOwl, VirusTotal; components valued: Customers, Timeline, Graph, Reports with customizable template, native backups, templates & taxonomy; best practice adopted: store case artefacts encrypted *outside* the platform with a reference in the case — [CERT.PT PDF](https://csirt.fct.pt/wp-content/uploads/2025/06/04-DFIR-IRIS-Jorge-Loureiro.pdf).
- Homelab "soc-deploy" project calls IRIS a "TheHive successor" with "cases, timelines, evidence hashing, IOC mgmt, MITRE ATT&CK mapping, multi-tenant, REST API" (author's view) — [github.com/distantgeek/soc-deploy](https://github.com/distantgeek/soc-deploy).
- Official docs (2026): v3 live demo at preview.dfir-iris.org; features "War Rooms: Real-time chat, slash commands, per-room teams"; docs include "Migrating to IRIS v3" and a "Legacy endpoint migration map"; docs state beta versions are not production-ready — [docs.dfir-iris.org](https://docs.dfir-iris.org/latest/). The preview instance dashboard shows "My open cases / My open alerts / Pending tasks / Closed (30d)", "Following", a dark-mode toggle and Notifications — [preview.dfir-iris.org](https://preview.dfir-iris.org/).
- Third-party ecosystem signals of demand for integration surface: Sumo Logic automation integration — [sumologic docs](https://www.sumologic.com/help/docs/platform-services/automation-service/app-central/integrations/dfir-iris/); Cyber Triage 3.15 pushes findings into IRIS timeline/IOCs — [cybertriage.com](https://www.cybertriage.com/blog/cyber-triage-3-15-import-defender-telemetry-more-soc-features/); community MCP server `iris-mcp` (2026-01) — [D#1005](https://github.com/orgs/dfir-iris/discussions/1005); IRIS-SOAR companion project — [github.com/swiftbird07/IRIS-SOAR](https://github.com/swiftbird07/IRIS-SOAR); a vendor sells a repackaged paid IRIS on AWS Marketplace — [aws marketplace](https://aws.amazon.com/marketplace/pp/prodview-jbgytgbtdymze).

### Inferences
- The "TheHive for triage, IRIS for investigation" framing in 2026 comparisons is the clearest market gap: nobody is seen as doing both well for free. A product with strong alert triage (table views, rules, SLA) *and* deep-investigation objects (timeline, assets, evidence) would address the most-repeated comparison critique.
- The CERT.PT practice of storing evidence outside the platform (encrypted, referenced) and Van Impe's reluctance to upload evidence suggest evidence handling should support external references/object-storage with hashing, not only uploads.
- The MCP server and n8n/Shuffle write-ups indicate real demand for IRIS to be driven by automation/agents; API consistency matters more than UI for that audience.

### Gaps
- Reddit (r/blueteamsec, r/cybersecurity, r/AskNetsec): three search attempts returned no Reddit threads, and reddit.com/old.reddit.com JSON endpoints returned non-JSON (blocked). I found no reliable Reddit sentiment.
- Hacker News: HN Algolia API returned zero stories or comments for "dfir-iris".
- LibHunt (aggregates Reddit mentions) and SOCFortress Medium returned HTTP 403.
- Discord/Matrix recaps, LinkedIn posts, and YouTube ("replace TheHive with DFIR-IRIS" video) comments were not retrievable.
- No 2024–2026 long-form independent review with hands-on limitations was found; the only hands-on reviews are 2022 (Van Impe) and 2023 (SANS ISC).

### Inferences
- Items that recur across *both* ecosystems and across 2017–2026 (SSO, image paste, task libraries, ATT&CK, bulk alert ops, auto-enrichment, metrics export, email, K8s) are the safest bets for a competitor; they are durable, not fad demands.
- Items asked in the brief that did NOT surface with measurable demand in either ecosystem: Kanban boards, keyboard shortcuts (only one IRIS bug), dark mode (IRIS v3 already has a toggle), STIX import (no IRIS issue found; CSV import exists), Plaso/super-timeline import (Timesketch link requested once in 2022). Treat these as low-evidence.
