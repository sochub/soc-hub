## Key Question 1 — Data model: columns of the timeline event table and linked objects

### Takeaway
A timeline event (`cases_events`) carries two timestamps (UTC `event_date` + "without tz" `event_date_wtz` + the `event_tz` offset string), title/content(markdown)/raw/source, a comma-separated `event_tags` text, a fixed-palette `event_color`, three booleans (`event_in_summary`, `event_in_graph`, `event_is_flagged`), a self-referential `parent_event_id` (child events), JSONB `modification_history` and `custom_attributes`, and links to assets/IOCs/category/comments via junction tables. The schema is byte-identical between v2.4.29 and v3; v3 only *adds* named "timelines" (`case_timelines` + `case_event_timelines` M2M).

### Cited Findings

**`CasesEvent` model (table `cases_events`) — identical in v2.4.29 and v3**
- Source: [iris-web v2.4.29 `source/app/models/cases.py` L171](https://github.com/dfir-iris/iris-web/blob/v2.4.29/source/app/models/cases.py) and [iris-backend develop `source/app/models/cases.py`](https://github.com/dfir-iris/iris-backend/blob/develop/source/app/models/cases.py). Exact columns:
  - `event_id` BigInteger PK
  - `parent_event_id` BigInteger FK→`cases_events.event_id`, nullable; `CheckConstraint('event_id != parent_event_id', name='check_different_ids')`; relationship `children` / backref `parent`
  - `event_uuid` UUID, `default=uuid.uuid4`, `server_default=gen_random_uuid()`, NOT NULL
  - `case_id` FK→`cases.case_id`
  - `event_title` Text
  - `event_source` Text
  - `event_content` Text (markdown; rendered with showdown in v2 UI)
  - `event_raw` Text
  - `event_date` DateTime (stored as UTC-normalised value)
  - `event_added` DateTime (set to `datetime.utcnow()` on create)
  - `event_in_graph` Boolean
  - `event_in_summary` Boolean
  - `user_id` FK→`user.id` (creator)
  - `modification_history` JSONB (audit trail; example `{"1704815112.677327": {"user": "administrator", "action": "created", "user_id": 1}}` per [docs API example](https://github.com/dfir-iris/iris-doc-src/blob/master/docs/api_reference/reference/v2.1.0/resources/case_timeline_events_add.yaml))
  - `event_color` Text
  - `event_tags` Text (comma separated)
  - `event_tz` Text (e.g. `"+00:00"`)
  - `event_date_wtz` DateTime ("without timezone": the local wall-clock time the analyst typed)
  - `event_is_flagged` Boolean, default False
  - `custom_attributes` JSONB
  - relationships: `case`, `user`, `category` (viewonly, via `case_events_category`), `children`
- Migrations that introduced later columns: `20a9c0fd56e1_add_parent_event_in_events.py`, `3204e9116233_add_event_flag.py`, `ca93d4b54571_add_created_by_in_events.py` — [iris-web v2.4.29 alembic dir](https://github.com/dfir-iris/iris-web/tree/v2.4.29/source/app/alembic/versions).

**[v3 only] Named multi-timelines inside a case**
- `CaseTimeline` (table `case_timelines`): `timeline_id` BigInteger PK, `case_id` FK (ondelete CASCADE, indexed), `name` String(128), `description` Text, `color` String(7) "#RRGGBB validated server-side", `is_default` Boolean, `created_at`, `created_by_id`; `UniqueConstraint('case_id','name')`. Docstring: "A case can hold any number of timelines. Events join multiple timelines through `CaseEventTimeline` so a single piece of evidence can appear on, e.g., the 'Attacker activity' and 'Network' views simultaneously without duplication. Every case gets a `is_default=True` row named 'Main' at creation time." — [iris-backend models/cases.py L165](https://github.com/dfir-iris/iris-backend/blob/develop/source/app/models/cases.py).
- `CaseEventTimeline` (table `case_event_timelines`): composite PK (`event_id` FK CASCADE, `timeline_id` FK CASCADE, indexed). "An event that appears on zero timelines is still rendered when the user selects 'All' but is invisible when any specific timeline is filtered." — same file L200.
- Migration `b2d8e91f5c20_add_case_timelines.py`, Create Date 2026-06-27, backfills one "Main" timeline per case; `c3e9fa0e6d31_backfill_events_to_default_timeline.py` — [iris-backend alembic](https://github.com/dfir-iris/iris-backend/tree/develop/source/app/alembic/versions).
- [v3 only] War rooms have a parallel model: `WarRoomTimeline`, `WarRoomTimelineEvent` (either references a case event via nullable `case_id`/`event_id` pair, or is free-form with `title`, `content`, `raw`, `source`, `tags`, `is_flagged`, `event_date`, `event_tz` String(16), `color` String(7), `category` String(64), `parent_id` SET NULL, `uuid`), plus `WarRoomTimelineEventAsset`/`...Ioc` M2M — [models/war_rooms.py L212-360](https://github.com/dfir-iris/iris-backend/blob/develop/source/app/models/war_rooms.py); migration `e5b2a41c9d7e_war_room_timeline_event_parity.py`.

**Allowed `event_color` values** (validated in `EventSchema.verify_data`; anything else is blanked to `''`): `'#fff'`, `'#1572E899'`, `'#6861CE99'`, `'#48ABF799'`, `'#31CE3699'`, `'#F2596199'`, `'#FFAD4699'` — [schema/marshables.py EventSchema](https://github.com/dfir-iris/iris-web/blob/v2.4.29/source/app/schema/marshables.py). v3 form offers the same six non-white values — [timeline-event-form.svelte L156](https://github.com/dfir-iris/iris-frontend/blob/master/src/routes/(app)/case/%5Bcase_id%5D/timeline/components/timeline-event-form.svelte).

### Inferences
- `event_date` is the canonical sort/filter key (UTC); `event_date_wtz`+`event_tz` exist purely to redisplay what the analyst typed. The pair is derived server-side: `validate_date()` does `isoparse(event_date + event_tz)` → `event_date`, and `isoparse(event_date)` → `event_date_wtz`.
- One category per event (unique `event_id` in `case_events_category`); multiple assets, multiple IOCs, multiple tags (text CSV), multiple timelines (v3).
- Tags are not a relation; each tag string is upserted into a global `Tags` table via `add_db_tag()` for autocomplete only.

### Gaps
- `custom_attributes` structure is admin-defined per object type ("event"); no fixed schema in source.

## Key Question 2 — UI behaviour (list view, filters, visualisation, grouping, legend, flags/summary, compact, CSV, tree/child events)

### Takeaway
[v2.4.x] The timeline page is a vertical card list ordered by `event_date` ASC with day badges, a code-editor filter bar (`key:value AND key:value`, no OR), compact/tree toggles persisted in `localStorage`, per-card actions (edit, add child, flag, comments, share link, markdown link, duplicate, delete), a multi-select mode for bulk delete / toggle-summary / toggle-graph / set-colour, CSV export (with or without user info), CSV import, and a separate vis.js "Visualize" page (grouped by asset or by category) that shows only `event_in_summary` events. [v3] The SvelteKit rewrite keeps the list/tree views, day grouping, quick in-page search with match navigation, structured filter fields, infinite-scroll pagination, a left sidebar of named timelines, deterministic per-category colours, CSV import/export via a column-picker modal — but drops the compact view and (as far as the source shows) the vis.js visualisation page for cases.

**Timezone handling (both versions)**
- Client sends `event_date` as `%Y-%m-%dT%H:%M:%S.%f` (naive) plus `event_tz` (`±HH:MM`); server computes `event_date = isoparse(event_date+event_tz)` (aware → stored normalised) and `event_date_wtz = isoparse(event_date)`; list responses return both as `%Y-%m-%dT%H:%M:%S.%f` strings — [EventSchema.validate_date](https://github.com/dfir-iris/iris-web/blob/v2.4.29/source/app/schema/marshables.py). The v2 CSV header literally labels the first column `event_date(UTC)`.
- `convert-date` returns `{date:'YYYY-MM-DD', time:'HH:MM:SS.mmm', tz:'+HH:MM'}`; v3 version additionally treats 10/13-digit integers as UTC epoch — [business/events.py events_convert_date](https://github.com/dfir-iris/iris-backend/blob/develop/source/app/business/events.py).

## Key Question 3 — API endpoints and payloads

### Takeaway

## Key Question 4 — Modules bulk-importing events, and timeline rendering in reports

### Takeaway
IRIS modules do not have a dedicated timeline-ingest API: the bundled `iris_evtx` module ships EVTX to **Splunk HEC**, not to the timeline; bulk population of the timeline is done through the REST API (`iris-client.add_event`, Velociraptor's `IRIS.Timeline.Add` artifact, or the CSV upload), while modules can mutate events via the `on_preload_event_create/update` and `on_postload_event_*` hooks. DOCX/HTML report templates receive a `timeline` list of event objects (`event.event_title`, `event.event_content`, `event.event_raw`, `event.event_date`, `event.event_source`, `event.category`, `event.event_tags`, `event.assets`, `event.custom_attributes`) ordered by `event_date`.

### Cited Findings

## Key Question 5 — Community feedback on timeline UX

### Takeaway
Open requests on the tracker centre on richer visualisation pivots (by IOC/tag), drag-and-drop of events onto parents, timezone/UTC-offset exposure in the API, and CSV export escaping; no maintainer responses are visible on the sampled issues, and maintainers' own direction (v3) went toward multiple named timelines, structured filters and pagination rather than Gantt/graph views.

### Cited Findings
- GitHub issue search "timeline" in `dfir-iris/iris-web` lists 102 results; timeline-specific items on page 1 include: #1147 "[FR] Hierarchical process-tree Graph: phases, risk colors, edge captions, and click-to-inspect"; #1089 "[#640][IMP] Enable image pasting in timeline description editor…" (Jun 2026); #1080 "[FIX] Fixed order of authentication methods for timeline filter endpoint" (merged Jun 2026); #1064 "[FIX] populate timeline event_source on csv upload" (Apr 2026); #1048 "992 timeline drag events onto parents" (PR, Mar 2026); #1047 "[#993][IMP] timeline visualization pivots and improves the UX/workflow" (PR, Mar 2026); #997 "[FR] Include UTC offset in timeline API query"; #993 "[FR] Visualize timeline by IOC & by Tag"; #992 "[FR] Event Timeline - Drag event onto parent"; #976 "[FR] Escape commas in Event Description field when exporting timeline via IRIS Web UI" — [issues?q=timeline](https://github.com/dfir-iris/iris-web/issues?q=timeline).
- #993 (opened 2025-12-05, label enhancement, open, no maintainer reply): "Add additional pivots to the visualization of the timeline, to include the associated IOCs and Tags on events." / "The visualization by Asset and by Category is very useful." A contributor (jasonwinget) linked ten fork commits (Mar 2026) covering "timeline visualization group routes, group controls, and a child-event visualization toggle" — [#993](https://github.com/dfir-iris/iris-web/issues/993).

- Early feature history shows users asked for a query filter ([#94](https://github.com/dfir-iris/iris-web/issues/94), delivered v1.4.2), IOC links in the timeline ([#50](https://github.com/dfir-iris/iris-web/issues/50), v1.4.3), and creator info in exports ([#65](https://github.com/dfir-iris/iris-web/issues/65), v1.4.3) — [changelog](https://docs.dfir-iris.org/changelog/).

### Inferences
- Features users ask for that a new implementation could build in from day one: drag-to-reparent, visualisation grouped by IOC/tag, timezone preserved in exports/API, robust CSV escaping, server-side pagination, and (from v3's own roadmap) multiple named timelines per case.
- No evidence was found of requests for Gantt views or Plaso import on the sampled pages.

### Gaps
- Only the first results page of the issue search and two issue bodies were read; there may be further UX threads (e.g. Discord/forum) not captured. No blog posts or videos specifically reviewing the timeline were retrieved (the web search returned only general listings).
