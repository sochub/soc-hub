# Evidence Attachments — Design

Date: 2026-10-02 · Status: approved in brainstorming · Branch: `feat/evidence-attachments` (stacked on `feat/threat-intel`, PR #36)

## Goal

Analysts attach evidence files to a case: screenshots, `.eml` phishing emails, PCAPs, logs, malware samples and exported reports. Teammates can list and download them. The system keeps a chain of custody: a server-computed SHA-256, an audit entry for every upload, download and delete, and soft delete. Uploaded content is never executed or rendered inline.

## Decisions (from brainstorming)

| Topic | Decision |
|---|---|
| Storage | `STORAGE_BACKEND=local\|s3`, default `local`. S3-compatible storage (AWS, MinIO, R2) uses the standard AWS credential chain, IAM role first. |
| Dangerous files | A "Malicious sample" flag at upload. Flagged files are stored and served only as an AES-256 ZIP with password `infected`. Unflagged files are served only as downloads. |
| Size | `MAX_UPLOAD_MB`, default 100. Uploads stream to storage. There is no per-tenant quota and no chunked upload in this version. |
| Threat intel | The SHA-256 of every upload is added to the case as a `file_hash` artifact. Normal enrichment rules apply: case artifacts are treated as TLP amber by default, so the lookup is manual. Only the hash is ever sent out. |
| Upload path | Through the backend: the browser sends the file to the API, which streams it to storage. No presigned direct-to-S3 uploads. |

## Storage (`app/storage/`)

```python
class Storage(Protocol):
    async def put(self, key: str, chunks: AsyncIterator[bytes]) -> int   # returns bytes written
    async def open(self, key: str) -> AsyncIterator[bytes]              # streams 64 KiB chunks
    async def delete(self, key: str) -> None
def get_storage() -> Storage   # chosen from settings, one instance per process
```

- **`LocalStorage(root)`**
  - Resolves `root / key`. It raises `StorageError` if the resolved path is not inside `root`, which covers `..`, absolute keys and symlinks.
  - Writes to `<path>.part` first, `fsync`s it, then `os.replace`s it into place. Missing parent directories are created with mode 0o700.
  - Blocking file I/O runs in `asyncio.to_thread`.
- **`S3Storage(bucket, region, endpoint_url, prefix)`**
  - Uses boto3 (already installed) and creates a fresh `boto3.session.Session()` per instance, which is thread-safe.
  - Uploads with `upload_fileobj`, multipart, with `ExtraArgs={"ServerSideEncryption": "AES256"}`, from a spooled temporary file. Downloads stream with `get_object()["Body"].iter_chunks(65536)`.
  - Blocking calls run in `asyncio.to_thread`.
  - Credentials come from the default boto3 chain only. The app never stores S3 keys.
- **Docker:**
  - Add a named volume `attachments_data` to `docker-compose.yml`, mounted at `/data/attachments` on both `backend` and `worker`.
  - Add the `STORAGE_*` and `MAX_UPLOAD_MB` env passthroughs.

## Upload pipeline (`app/services/attachments.py`)

1. **Sanitise the filename.** Take the basename after both `/` and `\\`, strip control characters (including CR/LF and NUL), trim to 255 UTF-8 bytes, and replace an empty or dot-only result with `attachment`.
2. **Stream the request body** (FastAPI `UploadFile`, read in 64 KiB chunks). For each chunk:
   - update a SHA-256 hash and a byte counter;
   - if the count exceeds `MAX_UPLOAD_MB * 1024 * 1024`, raise `TooLarge`;
   - if the file is **not** malicious, pass the chunk through to `storage.put`.
3. **Malicious files.** Write the incoming chunks to a `tempfile.SpooledTemporaryFile(max_size=8 MiB)`. When the stream ends, build an AES-256 ZIP of it with `pyzipper.AESZipFile(..., encryption=pyzipper.WZ_AES)` and password `b"infected"`. The ZIP has one member, the sanitised filename. `storage.put` then receives the ZIP's bytes.
4. **Size outcomes.**
   - Zero bytes → `EmptyFile`.
   - `TooLarge` or `EmptyFile` → delete any partial object (`storage.delete(key)`, ignoring errors) and write no DB row.
5. **Write the database rows.** Insert the `case_attachments` row. Call `add_artifact_to_case(db, case=case, artifact_type=ArtifactType.FILE_HASH, value=sha256, description=f"SHA-256 of attachment {filename}", user_id=uid)`, which deduplicates on its own. Add a `TimelineEvent(event_type="attachment_added", content=f"Attached {filename} (sha256 {sha256[:12]}…)")`. Add an audit log entry. Commit once.
6. **If the commit fails** after `put` succeeded, delete the stored object (best effort) and re-raise.

New dependency: `pyzipper`, pinned to an exact version in `backend/requirements.txt`. `pip-audit` must report it clean.

## API (`app/api/v1/attachments.py`, mounted at `/api/v1/cases/{case_id}/attachments`)

Every endpoint resolves the case with `Case.id == case_id AND Case.tenant_id == get_effective_tenant_id`, and returns 404 if it doesn't match. Attachments are filtered by `case_id` and `tenant_id`.

| Method and path | Role | Behaviour |
|---|---|---|
| `POST /` | analyst+ | Multipart fields: `file` (required), `is_malicious` (bool form field, default false), `description` (optional, ≤1000 chars). Returns **201** with the attachment JSON. Errors: **413** `"File exceeds {N} MB"`, **422** `"Empty file"`, **404** for a case that doesn't exist or belongs to another tenant. |
| `GET /` | any member | Returns `{max_upload_mb, items: [AttachmentOut]}`, newest first. `?include_deleted=true` is honoured only for admins; non-admins get 403 when they pass it. |
| `GET /{id}/download` | any member | Streams the stored bytes. Responses below. A deleted attachment or a row from another tenant returns 404. |
| `DELETE /{id}` | analyst+ | Sets `deleted_at` and `deleted_by`, writes a timeline event `attachment_deleted` and an audit entry, and returns 204. The stored object is kept. An already-deleted attachment returns 404. |

**Download responses.** These headers are on every download:

```
Content-Type: application/octet-stream
X-Content-Type-Options: nosniff
Content-Security-Policy: sandbox
Cache-Control: no-store
X-Content-SHA256: <original sha256>
```

| Attachment | `Content-Disposition` |
|---|---|
| Normal | `attachment; filename*=UTF-8''<percent-encoded sanitised name>` |
| Malicious | `attachment; filename*=UTF-8''<name>.zip`; the body is the stored encrypted ZIP |

**`AttachmentOut`:** `{id, case_id, filename, content_type, size_bytes, sha256, is_malicious, description, uploaded_by, uploaded_by_email, created_at, deleted_at, deleted_by, deleted_by_email}`. It never contains `storage_key`.

**Audit:** `create_audit_log(entity_type="attachment", entity_id=id, action="upload"|"download"|"delete", tenant_id, user_id, changes={"filename", "sha256", "is_malicious", "case_id"})`.

**Logging:** one INFO line per operation: `attachment <op> tenant=%s case=%s id=%s size=%s malicious=%s outcome=%s`. File contents and file names are never logged.

## nginx (frontend image)

- In `frontend/nginx/default.conf.template`, the `location /api/v1/` block gets `client_max_body_size ${MAX_UPLOAD_MB}m;` and `proxy_request_buffering off;`.
- Convert it to a template with `envsubst`, following the nginx image's `/etc/nginx/templates/*.template` convention, with `MAX_UPLOAD_MB` defaulting to 100 in compose. Restrict the substitution to that variable, so nginx's own `$host`-style variables are left alone.
- `proxy_read_timeout` and `proxy_send_timeout` are set to 300s for `/api/v1/`.

## UI

- **Evidence tab** on `CaseDetail`, next to Artifacts. It contains a new `frontend/src/features/cases/CaseEvidence.tsx`.
- **Upload zone** (analysts and above):
  - drag-and-drop or a file picker;
  - a "Malicious sample" checkbox with the hint "Stored and downloaded as a ZIP, password `infected`";
  - an optional description;
  - a client-side size check against `max_upload_mb`;
  - an XHR progress bar (axios `onUploadProgress`);
  - a 413 or 422 shows the response `detail`.
- **Evidence table:**
  - Columns: name, size (human-readable), SHA-256 (first 12 characters, with a copy button), uploaded by and when, a red "malicious" badge, Download, and Delete (analysts and above).
  - Delete uses an inline confirm.
  - Admins get a "Show deleted" toggle; deleted rows are greyed out and show "deleted by X".
- **Download:**
  - `api.get(..., {responseType: 'blob'})`, then an object URL saved through a temporary `<a download>`.
  - The file is never opened in a tab.
  - The filename comes from `Content-Disposition`.
  - For flagged files the button reads "Download (ZIP, pw: infected)".
- Uses the light Telemetry Console theme, like the other case tabs.

## Testing

No test touches the network or real S3. Storage tests use a `tmp_path` root. DB rows are deleted by their exact ids.

- **`LocalStorage`:**
  - round trip;
  - rejects `../x`, `/abs` and a key that resolves through a symlink to outside the root;
  - a partial `.part` file is never visible under the final name if writing fails mid-stream.
- **`S3Storage`:** against a fake client (monkeypatched `boto3.session.Session`):
  - `upload_fileobj` called with `ServerSideEncryption=AES256`, the bucket and the prefixed key;
  - the endpoint URL is passed through;
  - downloads stream chunks.
- **Filename sanitising:** `../../etc/passwd` → `passwd`, `a\r\nb.txt` → `ab.txt`, `C:\\x\\y.exe` → `y.exe`, unicode kept, a 300-character name trimmed, `""` and `".."` → `attachment`.
- **API (in-process, `ASGITransport` with dependency overrides, `STORAGE_LOCAL_PATH` set to a temp directory):**
  - **Upload:**
    - the SHA-256 and size match the bytes sent;
    - a file just over the limit gets 413 and no stored object and no row remain;
    - an empty file gets 422;
    - a viewer gets 403 on POST and DELETE;
    - another tenant's case gets 404.
  - **Download:**
    - the response headers exactly match the spec;
    - the body equals the original bytes;
    - a malicious upload's download is a ZIP that `pyzipper` opens with `b"infected"`, and its member's bytes equal the original.
  - **Delete:** the row is hidden from GET, download returns 404, and a second delete returns 404. An admin with `include_deleted=true` sees the row with `deleted_by`; a non-admin passing that flag gets 403.
  - **Records:**
    - audit rows exist for upload, download and delete;
    - timeline events exist for upload and delete;
    - one `file_hash` artifact is created and is reused when the same bytes are uploaded again;
    - the list response contains `max_upload_mb`.
- **Frontend:** `npm run build` and lint.

## Out of scope

- Antivirus scanning.
- Previews and thumbnails.
- Per-tenant quotas.
- Chunked or resumable uploads above 1 GB.
- Purging soft-deleted objects.
- Presigned direct-to-S3 uploads.
- Attachments on alerts or IOCs; this version is for cases only.
